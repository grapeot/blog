# 站点的 LLM Friendliness 工程设计

## 业界常见做法

为了方便LLM和Agent上网，业界形成了一些常见的LLM friendliness做法，主要在发现，解析和接口三个方面：

- 站点导览规范（llms.txt）：在网站根目录下放置llms.txt，介绍网站主题、结构概要、代表性作品和阅读指南。
- Markdown 格式支持：提供传统 HTML 之外的纯 Markdown 格式正文。常见方法有生成静态孪生页面（如 <slug>.md）或通过 HTTP 内容协商，当 Accept 头包含 text/markdown 时返回纯文本。
- 结构化数据标注：使用 schema.org 规范和 JSON-LD 标签，为文章添加元数据，包括标题、作者、发布日期和正文类型。
- 爬虫权限和内容信号：在 robots.txt 中指定各大 AI 厂商的爬虫访问策略，或使用元标签声明内容授权和索引规则。
- 内容接口化：将内容封装成 MCP 服务或专用 API，便于具备工具调用能力的智能体直接检索。
- 索引协议和订阅源：维护规范的 XML Sitemap 和 RSS/Atom 订阅源，帮助抓取系统稳定获取全站链接树和更新信息。
- 语义化 HTML：使用清晰的原生 HTML 标签，避免不必要的 DOM 嵌套和客户端动态渲染，降低解析器提取正文的难度。

这些措施分别解决了导航概览、格式清洗和程序化接入的需求。

## 从服务器数据出发的方法论

在考虑和实施具体解决方案时，我们依赖自有服务器日志和实际访问数据来进行决策。后台日志可以让我们直接查看有哪些AI爬虫来访、访问频率有多大、它们具体抓取的页面有哪些；同时，访问数据则能展示AI助手为我们带来了多少真实的读者。

结合公开的行业证据进行交叉观察，一些受关注的高频单点做法（比如只放置一个`llms.txt`文件）对推动内容被 AI 回答引擎引用几乎没有可测量的杠杆。大语言模型在生成问答时，内容是否能进入检索并被引用，主要取决于内容能否顺利进入通用搜索引擎的索引、文章本身的信息质量，以及全网对该内容的真实讨论与提及。

因此，我们的设计原则是从数据和实际收益出发，把工程重点放在扎实的抓取发现层与干净的机器易读正文上。只要主流爬虫能低成本发现页面，自动化程序在请求内容时能直接拿到无污染的纯文本结构，就能切实降低解析成本，不需要跟随业界概念频繁调整方案。

## 站点现有的具体设计

yage.ai（Computing Life）是一个基于 Pelican 的静态博客，以中文为主，含大量中英配对文章，已有三百多篇技术与随笔，并在 /share/ 下发布长篇深度调研。结合静态网站的特点，我们做了一些简单直接的工程来分别解决 AI 生态中的发现、语义识别和正文获取：

第一，爬虫放行。在 `robots.txt` 中明确允许 GPTBot、ClaudeBot、PerplexityBot 和 Google-Extended 等爬虫抓取，并指向 `sitemap.xml` 位置，便于它们发现全部内容。

第二，全站地图和增量订阅。站点自动生成全量 `sitemap.xml`，并提供 RSS 和 Atom 订阅源（`/feeds/rss.xml`、`/feeds/atom.xml`）。sitemap 给出全站 URL 的静态快照，RSS/Atom 则按时间倒序维护最新内容，方便抓取系统按需全量回溯或增量追踪。

第三，结构化元数据标注。系统为每篇文章生成嵌入式JSON-LD结构化数据，遵循schema.org的BlogPosting规范，标注标题、作者、发布时间与描述；页面同时包含Open Graph、Twitter Card元数据与canonical规范链接。机器可直接提取标准化字段，不必依靠规则猜测文章属性。

第四，双语文章互链。网站有大量中英双语配对文章，用标准的 hreflang 标签进行互链。当爬虫抓取任意一种语言的版本时，可直接发现对应的翻译版本，避免多语言内容在索引中的割裂。

第五，显式摘要设计。每篇文章在构建阶段保留独立的 Summary 字段，供描述标签和列表页调用。结构化摘要提供凝练的信息切片，帮助大模型和爬虫在进入长文本前建立快速语义锚点。

第六，站点导览文件。在站点根目录配置 `llms.txt`，说明站点主题、使用语言、核心模块入口与代表作列表，为具备特定读取能力的智能体提供清晰的站点导航。

第七，Markdown 孪生页与自动发现。静态编译输出 HTML 文章页，同时产出同路径的 `<slug>.md` 纯 Markdown 文件。在 HTML 页面 `<head>` 中加入 `<link rel="alternate" type="text/markdown" href="...md">` 标签。智能体或解析工具访问网页时，可通过 HTML 头部自动发现 Markdown 地址，直接获取剥离了导航栏、页眉页脚与样式的纯净正文，消除 HTML 转 Markdown 带来的排版噪声与结构失真。

## 实际观测到的效果

通过观察本地nginx log和GA4，可以大致了解这些设计在实际场景中的运行情况。

全站整体来看，服务器每两周处理的请求量在百万级别。

从爬虫的角度来看，我们在两周内连续观察到许多流行的 AI 爬虫一直在进行抓取。这些 AI 爬虫包括 ClaudeBot 和 Claude-User、Bytespider、meta-externalagent、ChatGPT 系列（包括 GPTBot、OAI-SearchBot 和 ChatGPT-User）、Perplexity、Amazonbot、Applebot 和 CCBot 等。每个爬虫在两周内的抓取次数从几百次到上万次不等，全站的主流 AI 爬虫在一期内抓取的次数达到数万次。

在机器友好的 URL 方面，包含 `llms.txt` 导览文件的根目录每两周被访问上百次。此外，每两周针对类似 `.md` 的纯文本孪生页的访问也有数百次。这说明自动化系统不仅抓取传统 HTML 页面，还通过机器友好的 URL 直接获取内容。

在最终的人类访问方面，来自各种AI助手的引荐流量每年也有几百人。在这些通过AI问答转化的人类访问者中，ChatGPT贡献的人数最多，其次是Gemini、Claude和Perplexity。

我们目前得到的数据可以展示出一个访问量的数量级和AI抓取的频率。这意味着我们的网站设计被现有的AI抓取和产品生态所使用。我们不会将这种现象直接归因于特定的设计决策，但会将其作为观察和优化我们的工程实现的实际参考。
